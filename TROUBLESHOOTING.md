# Troubleshooting Guide

## Common Issues and Solutions

### 1. MongoDB Containers Fail to Start

**Error:**
```
BadValue: security.keyFile is required when authorization is enabled with replica sets
```

**Solution:**
The MongoDB keyFile is automatically generated by the `start.sh` script. If you see this error:

1. Ensure you're using `./start.sh` to start the cluster (not `docker-compose up` directly)
2. If the issue persists, manually generate the keyFile:
   ```bash
   bash ./scripts/generate-keyfile.sh
   ```
3. Verify the keyFile exists and has correct permissions:
   ```bash
   ls -l ./mongodb-keyfile/mongodb-keyfile
   # Should show: -rw------- (600 permissions)
   ```

### 2. "docker-compose: command not found"

**Solution:**
Depending on your Docker version, use one of these commands:

```bash
# Newer Docker versions (Docker Compose V2)
docker compose up -d

# Older versions (Docker Compose V1)
docker-compose up -d
```

Update `start.sh` to use the correct command for your system.

### 3. Permission Denied on MongoDB KeyFile

**Error:**
```
permissions on /data/mongodb-keyfile are too open
```

**Solution:**
The keyFile must have 600 permissions (or 400, but 600 works better with Docker):

```bash
chmod 600 ./mongodb-keyfile/mongodb-keyfile
```

Then restart the containers:
```bash
docker compose restart mongo1 mongo2 mongo3
```

### 4. Replica Set Initialization Fails

**Error:**
```
Error response from daemon: container XXX is not running
```

**Solution:**
1. Check container logs to see why MongoDB failed to start:
   ```bash
   docker logs mongo1
   docker logs mongo2
   docker logs mongo3
   ```

2. Common causes:
   - Missing or incorrect keyFile (see issue #1)
   - Port already in use
   - Insufficient resources

3. Clean start:
   ```bash
   docker compose down -v
   ./start.sh
   ```

### 5. Cannot Connect to MongoDB

**Error:**
```
MongoServerError: Authentication failed
```

**Solution:**
The default credentials are:
- **Username:** `admin`
- **Password:** `password123`

Connection string:
```
mongodb://admin:password123@localhost:27017/?authSource=admin
```

For replica set:
```
mongodb://admin:password123@localhost:27017,localhost:27018,localhost:27019/?replicaSet=rs0&authSource=admin
```

### 6. Test Orchestrator Build Fails

**Error:**
```
ERROR: failed to solve: failed to compute cache key
```

**Solution:**
Ensure all required files exist:
```bash
ls test-orchestrator/
# Should show: Dockerfile, requirements.txt, load_generator.py, test_framework.py
```

Rebuild the image:
```bash
docker compose build test-orchestrator
docker compose up -d test-orchestrator
```

### 7. Grafana Dashboard Not Loading

**Solution:**
1. Check if Grafana is running:
   ```bash
   docker ps | grep grafana
   ```

2. Check Grafana logs:
   ```bash
   docker logs grafana
   ```

3. Verify dashboard files exist:
   ```bash
   ls monitoring/grafana/dashboards/
   ```

4. Restart Grafana:
   ```bash
   docker compose restart grafana
   ```

5. Access Grafana at http://localhost:3000 (admin/admin)

### 8. Prometheus Not Collecting Metrics

**Solution:**
1. Check if MongoDB exporters are running:
   ```bash
   docker ps | grep exporter
   ```

2. Verify MongoDB is accessible from exporters:
   ```bash
   docker exec mongodb-exporter1 wget -qO- http://mongo1:27017
   ```

3. Check Prometheus targets:
   - Navigate to http://localhost:9090/targets
   - All targets should show "UP" status

4. Restart the monitoring stack:
   ```bash
   docker compose restart prometheus mongodb-exporter1 mongodb-exporter2 mongodb-exporter3
   ```

### 9. Chaos Scenarios Not Working

**Pumba Network Chaos Fails:**

**Error:**
```
tc command not found
```

**Solution:**
Pumba requires privileged mode (already configured in docker-compose.yml). If issues persist:

1. Check Pumba logs:
   ```bash
   docker logs pumba
   ```

2. Verify Pumba can access Docker socket:
   ```bash
   docker exec pumba ls -l /var/run/docker.sock
   ```

3. Alternative: Use direct `docker exec` commands instead of Pumba:
   ```bash
   # Stop a container
   docker stop mongo1

   # Add network delay
   docker exec mongo1 tc qdisc add dev eth0 root netem delay 200ms
   ```

### 10. High Resource Usage

**Issue:** System becomes slow or unresponsive

**Solution:**
1. Check current resource usage:
   ```bash
   docker stats
   ```

2. Reduce resource limits in `docker-compose.yml`:
   ```yaml
   deploy:
     resources:
       limits:
         cpus: '0.5'    # Reduced from 1.0
         memory: 256M   # Reduced from 512M
   ```

3. Reduce load generator intensity:
   ```bash
   docker exec test-orchestrator python load_generator.py \
     --threads 5 \
     --ops-per-sec 50 \
     --duration 60
   ```

### 11. Ports Already in Use

**Error:**
```
Bind for 0.0.0.0:27017 failed: port is already allocated
```

**Solution:**
1. Find what's using the port:
   ```bash
   # Linux/Mac
   sudo lsof -i :27017

   # Windows
   netstat -ano | findstr :27017
   ```

2. Stop the conflicting service or change ports in `docker-compose.yml`:
   ```yaml
   ports:
     - "27027:27017"  # Changed from 27017:27017
   ```

### 12. Results Not Being Saved

**Issue:** No JSON files in `./results/` directory

**Solution:**
1. Verify results directory exists and is writable:
   ```bash
   ls -ld ./results/
   mkdir -p ./results/
   chmod 755 ./results/
   ```

2. Check test orchestrator logs:
   ```bash
   docker logs test-orchestrator
   ```

3. Ensure tests are completing:
   ```bash
   docker exec test-orchestrator python load_generator.py --duration 10
   ls -l ./results/
   ```

## Getting Help

If you encounter an issue not listed here:

1. **Check Logs:**
   ```bash
   docker compose logs -f
   ```

2. **Check Container Status:**
   ```bash
   docker compose ps
   ```

3. **Verify Network:**
   ```bash
   docker network inspect nosql-cluster-simulations_mongo-cluster
   ```

4. **Clean Restart:**
   ```bash
   docker compose down -v
   rm -rf ./mongodb-keyfile/mongodb-keyfile
   ./start.sh
   ```

5. **Report Issue:**
   - Include error messages
   - Include relevant logs
   - Include system info (OS, Docker version)
   - Create an issue on GitHub

## System Requirements

**Minimum:**
- Docker Engine 20.10+
- Docker Compose 2.0+
- 4GB RAM
- 10GB disk space

**Recommended:**
- Docker Engine 24.0+
- Docker Compose 2.20+
- 8GB RAM
- 20GB disk space
- Multi-core CPU

## Quick Diagnostic Commands

```bash
# Check all services are running
docker compose ps

# View logs for all services
docker compose logs -f

# Check MongoDB replica set status
docker exec mongo1 mongosh -u admin -p password123 --authenticationDatabase admin --eval "rs.status()"

# Check if primary exists
docker exec mongo1 mongosh -u admin -p password123 --authenticationDatabase admin --eval "rs.isMaster().primary"

# Test connectivity
docker exec test-orchestrator ping -c 3 mongo1

# Check MongoDB authentication
docker exec mongo1 mongosh -u admin -p password123 --authenticationDatabase admin --eval "db.adminCommand('ping')"

# View cluster status script
./status.sh
```
